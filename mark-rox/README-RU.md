# MARK ROX — сайт и AdminPro

Готовая сборка исходников: галерея, каталог, заявки, защищённая админ-панель и серверная база данных. Это не опубликованный сайт и не настроенный хостинг. Домен, HTTPS и каналы уведомлений подключаются владельцем при запуске. Оплата онлайн намеренно не реализована: посетитель отправляет запрос, а наличие, итоговая цена и доставка согласуются отдельно.

## Сначала посмотрите

Рядом с проектом в архиве:
- `mark-rox-preview.html` — самостоятельный просмотр публичного сайта. English по умолчанию, переключатель RU.
- `mark-rox-admin-preview.html` — отдельный просмотр AdminPro. Нажмите **Open local admin preview**. Поля логина/пароля в этом просмотре демонстрационные; настоящая защита реализована на сервере.

В публичном сайте нет кнопки **Admin Preview** и нет ссылки на админку. Проданные работы показываются с большой полупрозрачной SOLD-плашкой по центру; сверху и снизу остаётся видна фотография.

**Важно о предпросмотрах:** это локальные демонстрации, не защищённые аккаунты. Изменения сохраняются только в браузере. Заявки не отправляются. Не вводите настоящие личные данные. Файловые HTML-страницы могут иметь отдельные хранилища в разных браузерах: для просмотра изменений используйте **View website** внутри самой демо-админки и кнопку «Назад» браузера для возврата. Не ожидайте синхронизации между двумя отдельно открытыми HTML-файлами. В серверной версии сайт и админка используют единую базу.

## Что реализовано

- Адаптивные главная, каталог, художник, контакт, карточка работы, список выбранного и форма запроса.
- English по умолчанию; русский переключается вручную и сохраняется в браузере.
- Выразительная крупная типографика, спокойный фон, графичные акценты.
- 7 работ Mark Rox из проверенных карточек Artevistas. Архив отделён от доступных к запросу работ.
- Категории, теги, поиск, сортировка, статусы `on_request / available / reserved / sold`.
- До 8 фотографий в карточке; обложка, миниатюры, просмотр, увеличение, переключение клавишами, открытие оригинала.
- Формы запросов о покупке, индивидуальных работах и сотрудничестве. Валидация, согласие, защита от простого спама и повторной отправки.
- AdminPro: создание/редактирование/удаление, публикация/черновик, изображения, цены, теги, EN/RU-тексты, портрет, контакты, заявки и статусы.
- Смена логина и пароля в разделе Account; отзыв всех активных сеансов после смены.
- SQLite: данные не пропадают при перезапуске сервера. Изображения сохраняются в `data/uploads`.
- Серверные уведомления в Telegram и/или email через Resend. Ключи не попадают в браузер.
- Сначала сохранение заявки, затем доставка уведомлений. Очередь, 5 попыток с задержкой и ручной повтор. Нельзя гарантировать единственную доставку при сбое после принятия внешним сервисом — номер заявки позволяет распознать повтор.
- Защита API: scrypt-хеш пароля, HttpOnly host-only cookie, SameSite Strict, Secure в production, CSRF, проверка Origin/Host, ограничение попыток, валидация файлов и входных данных, экранирование вывода.
- Метаданные страниц, sitemap, robots; запрет индексирования админки. Страницы интерактивные: содержимое каталога отрисовывается JavaScript, полноценного серверного SEO-пререндеринга нет.

## Локальный запуск — без установки зависимостей

Нужен **Node.js 24+**. Все серверные зависимости встроены в Node; `npm install` не требуется.

```bash
cd mark-rox
cp .env.example .env
npm run admin:setup
npm start
```

`admin:setup` спросит логин и дважды пароль, скрывая ввод. Пароль — минимум 12 символов. Сохранится только scrypt-хеш. Откройте:

- сайт: `http://localhost:3000`
- AdminPro: `http://adminpro.localhost:3000`

Современные браузеры направляют `*.localhost` на локальный компьютер. Если ваша система этого не делает, добавьте `127.0.0.1 adminpro.localhost` в hosts либо используйте `http://localhost:3000/admin` **только в development**. В production такой путь на публичном домене закрыт; админка работает на отдельном `ADMIN_URL`.

Не публикуйте демонстрационные HTML как рабочую платформу. Для настоящих заявок и общего каталога запускайте `server.mjs`.

## Получение оригинальных фотографий

В сборке сохранены реальные URL фотографий Artevistas, не AI-генерации. Среда разработки не смогла скачать файлы из интернета, поэтому **фотографии пока не включены в архив**. В предпросмотре нужен доступ к Artevistas; если загрузка запрещена сетью или галереей, виден честный текстовый резервный экран.

После запуска на компьютере с доступом к интернету:

```bash
npm run assets:download
npm run preview:build
```

Первая команда скачивает оригиналы в `public/assets` и создаёт соответствие ссылок локальным файлам. Повторный запуск безопасен: имеющиеся изображения не скачиваются снова. Вторая встраивает скачанные фото в HTML-предпросмотры. Для новых работ загружайте изображения через админку. Перед публикацией подтвердите права на использование фотографий и текстов с автором/галереей. Визуальная проверка оригинальных фото и hotlink-доступности необходима после их загрузки.

## Включить реальные заявки

В `.env` укажите:

```dotenv
PRIVACY_CONTROLLER=Юридическое имя оператора сайта
PRIVACY_CONTACT=реальный-email-оператора
PRIVACY_RETENTION_DAYS=180
INQUIRIES_ENABLED=1
```

Без имени оператора, корректного email и флага приём заявок блокируется. Срок 180 дней — технический исходный параметр, а не юридическая рекомендация: настройте его и согласуйте политику для своей юрисдикции. Просроченные заявки автоматически удаляются из базы. Копии в Telegram, почте и резервных копиях необходимо удалять отдельно по вашей политике.

Можно принимать заявки только в админку без внешних уведомлений. Для Telegram заполните `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`. Получите токен в BotFather, добавьте бота в нужный чат, дайте разрешение отправлять сообщения. Не размещайте токен в публичных настройках и не присылайте его в чат.

Для email заполните `RESEND_API_KEY`, `EMAIL_FROM`, `EMAIL_TO`. Домен отправителя нужно подтвердить в Resend. Если получателей несколько, перечислите через запятую. После изменения `.env` перезапустите процесс. Сделайте отдельную настоящую тестовую заявку и проверьте получение сообщений. В данной сборке внешняя отправка проверена имитацией ответов провайдеров, не вашими реальными аккаунтами.

## Публикация на домене и adminpro

1. Выберите Node-хостинг/VPS с **постоянным диском**. Статический хостинг и эфемерные serverless-инстансы без диска не подходят для этой SQLite-конфигурации.
2. Настройте DNS основного домена и `adminpro.<ваш-домен>` на сервер. HTTPS нужен обоим.
3. Укажите `NODE_ENV=production`, `PUBLIC_URL=https://<ваш-домен>`, `ADMIN_URL=https://adminpro.<ваш-домен>`.
4. Запустите Node под менеджером процессов. Reverse proxy должен сохранять Host, завершать TLS и перезаписывать, а не дополнять входящий X-Forwarded-For.
5. Настройте `TRUST_PROXY=1` только для доверенного прокси, закрыв прямой доступ к Node извне. Пример конфигурации Caddy включён.
6. Создайте админа, смените/проверьте пароль. Убедитесь, что `/api/admin/*` на публичном домене возвращает 404.
7. Проверьте фотографии, права, цены, статусы, тексты, контакты, политику данных и тестовую доставку уведомлений. Сайт не синхронизирует цены с Artevistas автоматически.
8. Сделайте резервное копирование: SQLite — через штатную команду `.backup`/SQLite backup API либо при остановленном сервере вместе с WAL/SHM; также сохраните `data/uploads`, `data/admin.json`, `.env` и `public/assets`. Храните копии зашифрованно и ограничивайте доступ. При восстановлении сначала остановите приложение.

Не запускайте несколько независимых контейнеров с разными копиями SQLite: изменения не будут синхронизироваться. Для масштабирования перенесите данные в PostgreSQL и изображения в объектное хранилище.

## Проверка

```bash
npm test
```

Интеграционные тесты запускают отдельный сервер с временной базой и вымышленными контактами; не меняют ваш каталог и не отправляют сообщения. Подробности тестов и ограничений — в `QA.md`.

## Структура

- `public/` — интерфейс, стили, исходный каталог и соответствие фото.
- `server.mjs` — HTTP, SQLite, закрытая админка, очередь уведомлений.
- `security.mjs` — пароли, проверка карточек, заявок и фото.
- `notify.mjs` — Telegram и Resend, только сервер.
- `seed.json` — начальные данные. Применяются один раз, при создании базы.
- `scripts/` — настройка администратора, загрузка фото, сборка предпросмотров.
- `tests/` — автоматические проверки.
- `research/SOURCES.md` — источники и границы проверки.

Нет установленных паролей по умолчанию, чужих токенов, аналитических трекеров или фиктивных отзывов. Не указаны вымышленные адреса, гарантии доставки, тиражи, сертификаты или контакты художника. Цены и доступность подтверждаются до приобретения.
